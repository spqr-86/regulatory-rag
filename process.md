# Процесс работы над задачами

Как в этом проекте задача проходит путь от идеи до кода. Файл читают агенты — он короткий
и описывает только порядок, а не содержание задач.

1. **Задачи живут в GitHub issues.** Не в TODO-комментариях, не в переписке, не в чьей-то
   голове. Порядок работ — `docs/roadmap.md`.
2. **Задача не грумлена — сначала груминг.** Роль и правила — `team/PM.md`, форма результата —
   `docs/task-template.md`. Грумленая issue содержит цель, проверяемые acceptance criteria,
   явное «вне объёма» и крайние случаи.
3. **Реализация — только по грумленой задаче.** Если по ходу выясняется, что задача
   двусмысленна, инженер не додумывает: возвращает её на груминг.
4. **Новая логика начинается с падающего теста** (см. `docs/how-to/run-tests.md`; база
   предсуществующих красных тестов зафиксирована в CLAUDE.md).
5. **Коммиты — регулярно**, по одному смысловому шагу; ветка на задачу, issue закрывается
   ссылкой из коммита или PR.
6. **Что не влезло** в задачу — отдельной follow-up issue, а не тихим расширением объёма.
