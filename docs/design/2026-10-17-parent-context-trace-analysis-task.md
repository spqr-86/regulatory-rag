Заказчик: Пётр. Результат: один отчёт `docs/evaluation/experiments/parent-context-trace-analysis-2026-10-17.md`.

## Входные данные

- `benchmarks/eval_v7_parent_on_2026-10-17.jsonl` и `benchmarks/eval_v7_parent_off_2026-10-17.jsonl` — один JSON-объект
  (несмотря на `.jsonl`): `aggregate` + `results[56]` (`answer`, `path`, `usage[]`, `prompt_tokens`, `correctness_*`,
  `faithfulness_*`, `answer_relevance_*`, `reference_status`).
- LangSmith, проекты `rag-parent-on-2026-10-17` и `rag-parent-off-2026-10-17` (ключ в `.env`): трейсы с контекстом,
  поданным генератору. Нет сети или трейсов — написать, не придумывать.
- Код флага: `src/v7/pack_context.py`, sidecar `chroma_db.snapshots/build-8cs1plb3/parent_context.json`.
- Эталон `tests/dataset.csv`; нормы — `source_docs/`.
- Итоги прогонов и разбор G001/G019: `benchmarks/` и handoff 17.10. Известно: корректность 9.43 (on) / 9.07 (off) на 14
  verified; G001 — настоящий выигрыш on (весь перечень п. 53); G019 — шум судьи.

## Что нужно выяснить

1. **Лишний контекст.** По каждому вопросу on vs off: число и размер фрагментов в контексте генератора (знаки/токены),
   доля слов контекста, реально использованная в ответе (цитаты `[Фрагмент N]`), дубли родителей, окна ≤3000 знаков,
   которые вытеснили другие источники. `prompt_tokens`, время и цена on vs off. Вывод: платим ли мы за лишнее и сколько.
2. **Вопросы с прежними проблемами** (ошибки golden 56 от 16.10: G001, G019, G020, G022, G023, G025, G026, G027, G033,
   G037, G038, G040, G005; разбор — `golden56-error-analysis-2026-10-16.md`, если файл есть). Для каждого: что изменилось
   с флагом, почему (по контексту в трейсе), лучше/хуже/шум.
3. **Где флаг мог навредить:** вопросы, где окно родителя вытеснило нужный чанк из другой нормы, сбило цитату или
   увеличило неподдержанные утверждения (faithfulness).
4. **Свои вопросы.** Предложить 10–15 новых вопросов (с ожидаемой нормой и пунктом из `source_docs/`), которые лучше всего
   различают on/off: перечни, табличные подпункты, ссылки «в соответствии с п. N», многопунктные нормы, а также
   негативные (где родитель только мешает). Для каждого — зачем и что ожидаем. Без запуска.
5. **Рекомендация:** включать ли флаг по умолчанию, при каких условиях, какая следующая проверка (бесплатная/платная).

## Ограничения

- Только чтение и анализ. **Платные прогоны (LLM, эмбеддинги, LangSmith-эксперименты) без «да» Петра не запускать.**
- Код проекта, `.env`, `chroma_db*` не менять. Временные скрипты — вне репозитория (`/tmp/codex-parent-trace/`).
- Не отправлять данные во внешние сервисы, кроме чтения трейсов LangSmith проекта Петра.
- Каждое число — со ссылкой на источник (поле файла, run id, `файл:строка`). Нет данных — «не проверено».
- Формат отчёта: «Итог» (5–8 строк), затем разделы 1–5, таблица по 56 вопросам — в приложении.
