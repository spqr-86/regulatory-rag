# Задача для Codex: метрики и диагностика подстановки родителя (`V7_PARENT_CONTEXT_ENABLE`)

Заказчик: Пётр. Ветка `feat/parent-context-flag` (не пушить, не мержить). Контекст: разбор трейсов
`v8-parent-on-40aeb103` / `v8-parent-off-bc6f274e` и `v8-parent3-on-5cd31d8d` / `v8-parent3-off-bf608bc0` (LangSmith) и
`docs/evaluation/experiments/parent-context-trace-analysis-2026-10-17.md`.

## Что сделать (три пункта, каждый отдельным коммитом)

1. **`retrieval_hit` занижает режим с флагом.** `replace_parents` (`src/indexing/parent_context.py`) схлопывает несколько
   детей одного родителя в один пассаж; в `chunk_ids` (`extract_chunk_ids`, `eval/run_retrieval_eval.py`) остаётся id только
   первого ребёнка, а метки эталона привязаны к id детей. Нужно: в пассаже родителя хранить список id всех поглощённых
   детей (напр. `metadata["child_chunk_ids"]`), в `extract_chunk_ids` для `retrieval_hit` раскрывать их, порядок и дедуп
   сохранить. Пример-артефакт: G052, метки `426-ФЗ.pdf#322/#323`, в on в выдаче только `#315`, хотя ответ процитировал
   ст. 27 ч. 4. Выдача для генератора не меняется. Тесты (TDD): родитель с тремя детьми → все три id; off-режим без изменений.
2. **Признак обрезки и счётчик слотов.** Родитель обрезается по `PARENT_MAX_CHARS` (≤3000). В 42 из 483 фрагментов
   on-контекста (8.7%, в основном 426-ФЗ и ТК) длина ≥2950, в таблице 776н обрыв посреди строки. Нужно: в `ParentStats`
   и в outputs eval/LangSmith (`parent_replaced`, … в `eval/ls/target.py`, `eval/run_v7_eval.py`) добавить `parent_truncated`
   (сколько родителей обрезано) и `parent_slots_lost` (на сколько пассажей меньше лимита после дедупа/бюджета). Тесты.
3. **Оффлайн-проверка «хватит ли топ-10» (без платных вызовов).** По сохранённым трейсам LangSmith (проекты выше,
   чтение разрешено) для каждого нормативного вопроса on: максимальный номер процитированного `[Фрагмент N]` (не путать с
   номерами документов вроде 2464, 1479). Известно из разбора: медиана 2, p90 13, в 15 из 17 ≤10. Дать таблицу по
   вопросам и вывод: безопасно ли `FINAL_MERGE_TOP_K` для режима on снизить до 10–12; перечислить вопросы, где нужен
   номер >10. Результат — раздел в `docs/evaluation/experiments/parent-context-trace-analysis-2026-10-17.md` или новый
   файл рядом. Не менять `FINAL_MERGE_TOP_K`.
