# Нарезка законов и правил из текста — дизайн (17.10.2026)

Статус: черновик. Индекс и `src/` не меняются; пробный прогон — отдельным скриптом, без
переиндексации (она только по «да» Петра).

## Проблема (замер на снимке `build-8cs1plb3`)

Нарезка делает HybridChunker с токенизатором MiniLM, бюджет даёт чанк ~200–480 знаков.
Структуру текста он не знает, поэтому:

- **G005, п. 16 Правил 2464** (`2464.md`, чанки 40–48): вводная «Внеплановый инструктаж … в
  случаях, обусловленных:» — чанк 40; пункты а)–з) — отдельные чанки 41–48 без вводной и без
  номера пункта. Поиск находит вводную, перечень в контекст не попадает; пункт «з) решением
  работодателя» сам по себе ни о чём.
- **G047, ст. 229 ТК**: статья нарезана на 23 чанка по 130–480 знаков, чанки обрываются
  посреди фразы («…организации или иного уполномоче» → «…федерального органа…»).
  Абзац «Комиссию возглавляет, как правило…» (чанк 1567) в индексе есть; в контекст он не
  попадает из-за 13 почти одинаковых чанков раздела III приказа 223н (вытеснение дублями —
  вероятная причина, не доказано).

Общий корень: единица нарезки — «сколько влезло в токены», а не единица нормы.
Заплатки (подтянуть соседей по `chunk_id`, дедуп) не лечат корень; решение Петра
17.10 — переделать нарезку.

## Решение

Свой парсер для законов, кодексов и правил из официального текста (pravo.gov.ru; txt/docx/md).
Docling остаётся для таблиц и приказов с вёрсткой.

Иерархия: Раздел → Глава → Статья «Статья N. Название» (или пункт «N.») → часть/пункт →
подпункт. Единица чанка — **норма**, не токены.

Правила чанка:

1. **Статья/пункт целиком**, если ≤ `LAW_CHUNK_MAX_CHARS` (≈1800 знаков; под эмбеддинг
   `text-embedding` с запасом, значение уточнить на замере).
2. **Перечень не режется от вводной.** Пункт со списком а)–я) — один чанк «вводная + все
   подпункты». Если не влезает — делится по подпунктам, и **каждый чанк начинается с
   вводной фразы и номера пункта** («16. Внеплановый инструктаж … обусловленных: е)
   произошедшими авариями…»).
3. **Длинная статья делится по частям** (1., 2. …), не по длине; часть, не влезающая в
   лимит, — по абзацам, каждый чанк с префиксом «Статья N. Название, часть M».
4. **Префикс в тексте чанка** — документ, глава, статья/пункт (как сейчас `heading_path`, но
   полный и без чужих разделов). Метаданные `article`, `part`, `item` сохраняются (контракт
   `annotate_article_parts` не ломаем).
5. **Проверка на сборке**: номера статей/пунктов из текста сверяются с оглавлением/сквозной
   нумерацией; пропуск или дубль — сборка падает (а не пишет молча кривой индекс).

## Тест-кейсы (пишутся до кода, TDD)

| Кейс | Вход | Ожидание |
|---|---|---|
| G005 | `source_docs/2464.md`, п. 16 | один чанк (или несколько, каждый с вводной), в тексте все а)–з) или вводная + подпункты чанка; нигде нет подпункта без вводной |
| G047 | ст. 229 ТК | чанки не обрываются посреди предложения; фраза «Комиссию возглавляет, как правило, государственный инспектор труда…» лежит в чанке с префиксом «Статья 229» |
| Нумерация | 2464, 223н-подобный список | `16\.` остаётся номером пункта, не «6.» |
| Сверка | ТК, 426-ФЗ, 69-ФЗ | число статей парсера = число статей оглавления; расхождение → ошибка |
| Инвариант | любой документ | конкатенация чанков (без префиксов) покрывает исходный текст без потерь |

## Пробный прогон (без индекса)

1. `scripts/probe_law_chunker.py <source> --items 16` печатает чанки п. 16 2464 и ст. 229 ТК.
2. Для 2464 вход — `source_docs/2464.md` (уже из pravo.gov.ru). Для ТК нужен официальный
   текст: в `source_docs` лежит только `тк рф.pdf`, пробу на нём помечать как «текст из PDF,
   не официальный»; официальный txt/docx — взять с pravo.gov.ru до реальной сборки.
3. Метрика пробы — тест-кейсы выше, не retrieval. Retrieval до/после на golden — только после
   переиндексации по «да».

## Открытые вопросы

- Лимит чанка в знаках и совместимость с текущим эмбеддером/реранкером (контекст
  `FINAL_MERGE_TOP_K`=24 при чанках в 4–5 раз длиннее: бюджет контекста генератора).
- Таблицы внутри законов (редко) — оставить Docling или выкидывать в приказной контур.
- Приказы (223н, 29н, 776н): парсер не трогает; их дефекты (таблицы) — отдельная линия.
- Редакции: pravo.gov.ru отдаёт действующую; приписки «(в ред. …)» — оставлять в тексте
  чанка или выносить в метаданные.
