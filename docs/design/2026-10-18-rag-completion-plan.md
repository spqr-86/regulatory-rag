# План доведения regulatory-rag до закрытия

Статус: предложен ассистентом 18.10.2026; ревью Codex 18.10 — «принять с правками»,
правки внесены. Пётр дал «да» на шаг 1, эмбеддинги шага 2, линии B–D и merge шага 3.
Остальные платные шаги — только после отдельного «да» с оценкой цены.

Граница закрытия: инкремент generic V7 на development-наборе. Независимой оценки
юридической точности план не даёт и не заявляет.

## Цель и критерий закрытия

Одна воспроизводимая цифра качества на проверенном наборе (baseline единого eval) и
не больше одного-двух улучшений, каждое подтверждённое или опровергнутое этой цифрой.
Проект закрыт, когда:

- baseline записан как отдельная серия, цифры в `docs/reference/FACTS.md` и README;
- решение по родительскому контексту принято по замеру против baseline (включить
  правило / включить инструмент / оставить выключенным) и записано в отчёте;
- ветки этого плана влиты в `main`, после merge повторён полный offline gate, временные
  worktree убраны, в основной копии нет незакоммиченных файлов от этой линии;
- у baseline заранее заданы минимальное покрытие оценивания и допустимая доля ошибок
  target/judge; G019 и неоценённый G022 разобраны;
- записана команда воспроизведения с версиями конфигурации, датасета LangSmith, снимка и
  sidecar; Grafana проверена вживую или явно оставлена отложенным обязательством.

## Что не делаем до закрытия

Новые эксперименты с нарезкой (`fix/chunk-structural-context`, парсер законов из
официального текста), новые судьи, новые документы в корпус, ReAct-цикл с открытым
числом шагов. Эти пункты остаются в `docs/roadmap.md` → «Парковка».

## Шаги

### 1. Калибровка судьи groundedness

Прогон `eval.ls.align_groundedness` на двух замороженных партиях:
`eval/runs/groundedness_alignment_2026-10-18/` (12 меток, все 1) и
`eval/runs/groundedness_alignment_2026-10-18b_ablation/` (7 меток, все 0), модель
`deepseek/deepseek-v4-pro`, ≈ $0.08 (потолок $0.20).

- Принято (предварительная проверка): оценены все 19 из 19 (`None` не исключаются из
  знаменателя, как в `eval/ls/align.py`), совпадений ≥ 17, отдельно FP из 7 и FN из 12;
  каждое расхождение разобрано.
- GR04–GR11 приняты Петром пакетно без просмотра — пересмотреть до вывода.
- Для использования groundedness как quality gate нужна свежая независимая ручная партия:
  абляция не покрывает естественные ошибки и перефразированные неподтверждённые утверждения.
- Не принято: правка промпта судьи → новая свежая партия, а не перепрогон старой
  (иначе подгонка под метки).
- Ставка модели добавлена в `src/pricing.py`, но runner не сохраняет usage и пишет
  результат только после всей партии: цена — оценка, потолок не гарантирован механизмом.
- Ограничение: партии не held-out и смещены (12 естественных pass + 7 искусственных
  fail абляцией); согласие на них — нижняя планка, не валидация судьи.

### 2. Retrieval-метки для 9 false-premise

G043, G044, G046, G066, G071, G076, G083, G107, G108 на активном снимке. Бесплатно.
Сомнительные кейсы — Петру по одному. Сейчас retrieval размечен для 66 из 75 применимых
(7 OOS неприменимы); без этого шага знаменатель писать явно.

### 3. Слить зависимые ветки

Порядок: PR #74 (`eval/golden-expert-import`) → PR #75 (remap на `build-j7ceu4r4`) →
PR для `docs/parent-context-verified-on2` (фикс дедупликации окон `ba25344` и отчёт on3;
ветка запушена, PR нет, в `origin/main` и `feat/unified-eval` фикса нет) →
rebase `feat/unified-eval` на `main` → PR единого eval → ревью → merge.

Конфликты (`git merge-tree`, ревью Codex): #74 и #75 конфликтуют в `DEFAULT_LABELS` —
вариант #75 теряет метки 50 новых regular-кейсов; #75 поглотить изменениями #74 или
слить первым, сохранив `eval/runs/gt_label_j7ceu4r4_2026-10-18/`. `ba25344` меняет
`tests/dataset.csv`: сохранить 165 строк / 82 verified и перенести новый G005 с
`ground_truth_extra`. После rebase — повторное ревью объединённого диффа.

Затем синхронизировать LangSmith: upsert изменённых examples (новые метки, G005),
проверка записанного и фиксация версии датасета — `eval/ls/run.py` останавливается при
расхождении локальных и удалённых inputs/outputs.

### 4. Baseline единого eval

Один прогон текущей системы (флаг родителя выключен, дефолтные effort) на всех 82
verified (66 regular / 9 false-premise / 7 OOS), всеми судьями, со снимком и хешем кода в
manifest. Dry-run показывает состав, а не цену: до «да» — отдельный расчёт бюджета;
без учёта usage и построчных checkpoints суммы называются оценками (ориентир $0.5–1).

- Результат: серия baseline, цифры с явными знаменателями и долей неоценённых кейсов.
- Повтор: минимум два прогона или явная пометка «один повтор, разброс не установлен»;
  решение Петра по цене.

### 5. Родитель по правилу

Сейчас `PARENT_CONTEXT_ENABLE` подменяет родителем все пассажи (`replace_parents` в
`src/v7/pack_context.py`). В on3 это дало контекст ×2.87 и цену pipeline +39 % при
correctness 9/14 → 11/14 и полноте ссылок 9/13 → 8/13 на одном повторе
(`docs/evaluation/experiments/parent-context-window-dedup-on3-2026-10-17.md`).

Правило: подменять только пассаж, который является обрывком — пункт перечня или строка
таблицы без вводной части, перечень, обрезанный по границе чанка. Признаки брать из
метаданных чанка и sidecar, без LLM. В активном индексе есть `type`, `element_type`,
`parent_section`, `heading_path`, частично `article`, `part`, `table_row_id`; признака
«обрывок» нет. Sidecar для `build-j7ceu4r4` отсутствует, старый хранит только
`parent_id`, `text`, `snapshot_sha256`.

Порядок: построить sidecar для активного снимка (признаки в sidecar — без реиндекса) →
проверить эвристику на размеченных парах ребёнок/родитель и на входах `pack_context` до
подстановки (сохранённые финальные контексты on3 уже прошли замену и бюджет — не годятся) →
платный прогон off / always-parent / rule на одних 82 кейсах, снимке, эталонах и судьях.
Исторический on3 контрольным плечом не служит (другой снимок, 26 кейсов, прежние судьи).

- Принято: correctness не хуже baseline, полнота ссылок не хуже, контекст и цена ниже,
  чем у always-parent. Допустимую регрессию, покрытие и порядок разбора ошибок задать до
  прогона.

### 6. (Опционально) Родитель по решению модели

Инструмент `expand_parent(chunk_id)` только в сложном пути, лимит 1–2 вызова на запрос,
результат проходит тот же `pack_context` и бюджет. Не открытый ReAct: контракт triage
(answered / needs_context / abstain) и детерминированный граф не меняются. Замер против
шагов 4 и 5, плюс латентность и число вызовов. Делается, только если шаг 5 оставил
явные промахи.

### 7. Закрытие

FACTS.md и README на цифры baseline и итог шага 5/6; отчёт в
`docs/evaluation/experiments/`; `docs/roadmap.md` — статус «закрыт»; уборка веток и
worktree (`regulatory-rag-chunkctx`, `regulatory-rag-golden`, этот worktree) по «да» Петра.

## Параллельная работа

Зависимости: 1, 2 и офлайн-часть 5 друг от друга не зависят; 3 требует готовых 2 и
ревью единого eval; 4 — после 1, 2, 3; платная часть 5 и шаг 6 — после 4.

| Линия | Исполнитель | Шаги | Где | Ограничения |
|---|---|---|---|---|
| A | главная сессия Claude | 1, затем 4 | этот worktree | только платные прогоны по «да»; разбор расхождений судьи |
| B | субагент Claude (read-only) | 2 | этот worktree, предложение в `eval/runs/false_premise_labels_2026-10-18/` | предлагает chunk_id с дословной цитатой на `build-j7ceu4r4`; записывает главная сессия после сверки; сомнительные — Петру |
| C | Codex | ревью кода `feat/unified-eval` перед PR | read-only по диффу от `0296bb0` | находки — файлом; правки делает главная сессия |
| D | Codex | офлайн-часть 5: режим «родитель по правилу» под флагом, TDD, анализ на сохранённых контекстах on3 | новый worktree от `feat/unified-eval` + merge `docs/parent-context-verified-on2` (фикс `ba25344`), ветка `feat/parent-rule` | без платных вызовов, `.env` не копировать, дефолт флага не менять |

Пересечения: B пишет только в `eval/runs/`, C ничего не пишет, D трогает
`src/v7/pack_context.py`, `src/indexing/parent_context.py` и тесты, которые единый eval
не менял. Но D наследует конфликт `tests/dataset.csv` при merge `ba25344`, а rebase
главной сессии меняет базу ревью C. Правила: у каждой линии закреплены SHA базы,
владелец worktree и момент интеграции; rebase/merge — только после завершения
читателей; финально повторить ревью объединённого диффа; снимки и sidecar заморозить,
записываемые кеши и output-каталоги у каждой линии свои. Узкое место — решения Петра; их собирать одним сообщением: «да» на шаг 1,
«да» на merge #74/#75, сомнительные метки пачкой.
