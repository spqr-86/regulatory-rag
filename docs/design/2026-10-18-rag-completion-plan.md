# План доведения regulatory-rag до закрытия

Статус: предложен ассистентом 18.10.2026, Пётр попросил зафиксировать и отдать на ревью
Codex. Не начат. Платные шаги выполняются только после отдельного «да» Петра с оценкой цены.

## Цель и критерий закрытия

Одна воспроизводимая цифра качества на проверенном наборе (baseline единого eval) и
не больше одного-двух улучшений, каждое подтверждённое или опровергнутое этой цифрой.
Проект закрыт, когда:

- baseline записан как отдельная серия, цифры в `docs/reference/FACTS.md` и README;
- решение по родительскому контексту принято по замеру против baseline (включить
  правило / включить инструмент / оставить выключенным) и записано в отчёте;
- ветки этого плана влиты в `main`, временные worktree убраны, в основной копии нет
  незакоммиченных файлов от этой линии.

## Что не делаем до закрытия

Новые эксперименты с нарезкой (`fix/chunk-structural-context`, парсер законов из
официального текста), новые судьи, новые документы в корпус, ReAct-цикл с открытым
числом шагов. Эти пункты остаются в `docs/roadmap.md` → «Парковка».

## Шаги

### 1. Калибровка судьи groundedness

Прогон `eval.ls.align_groundedness` на двух замороженных партиях:
`eval/runs/groundedness_alignment_2026-10-18/` (12 меток, все 1) и
`eval/runs/groundedness_alignment_2026-10-18b_ablation/` (7 меток, все 0), модель
`deepseek/deepseek-v4-pro`, ≈ $0.08 (потолок $0.20).

- Принято: согласие ≥ 0.85 и разобраны все расхождения (false pass / false fail).
- Не принято: правка промпта судьи → новая свежая партия, а не перепрогон старой
  (иначе подгонка под метки).
- До прогона: добавить ставку модели в `src/pricing.py`, иначе стоимость будет $0.
- Ограничение: партии не held-out и смещены (12 естественных pass + 7 искусственных
  fail абляцией); согласие на них — нижняя планка, не валидация судьи.

### 2. Retrieval-метки для 9 false-premise

G043, G044, G046, G066, G071, G076, G083, G107, G108 на активном снимке. Бесплатно.
Сомнительные кейсы — Петру по одному. Без этого retrieval-метрики baseline считаются по
73 из 82 кейсов, и это надо писать явно.

### 3. Слить зависимые ветки

Порядок: PR #74 (`eval/golden-expert-import`) → PR #75 (remap на `build-j7ceu4r4`) →
PR для `docs/parent-context-verified-on2` (фикс дедупликации окон `ba25344` и отчёт on3;
ветка запушена, PR нет, в `origin/main` и `feat/unified-eval` фикса нет) →
rebase `feat/unified-eval` на `main` → PR единого eval → ревью → merge. Push и merge —
по «да» Петра.

### 4. Baseline единого eval

Один прогон текущей системы (флаг родителя выключен, дефолтные effort) на всех 82
verified (66 regular / 9 false-premise / 7 OOS), всеми судьями, со снимком и хешем кода в
manifest. Цена — оценка dry-run перед «да» (ориентир $0.5–1).

- Результат: серия baseline, цифры с явными знаменателями и долей неоценённых кейсов.
- Повтор: минимум два прогона или явная пометка «один повтор, разброс не установлен»;
  решение Петра по цене.

### 5. Родитель по правилу

Сейчас `PARENT_CONTEXT_ENABLE` подменяет родителем все пассажи (`replace_parents` в
`src/v7/pack_context.py`). В on3 это дало контекст ×2.87 и цену pipeline +39 % при
correctness 9/14 → 11/14 и полноте ссылок 9/13 → 8/13 на одном повторе
(`docs/evaluation/experiments/parent-context-window-dedup-on3-2026-10-17.md`).

Правило: подменять только пассаж, который является обрывком — пункт перечня или строка
таблицы без вводной части, перечень, обрезанный по границе чанка. Признаки брать из
метаданных чанка и sidecar, без LLM. Сначала офлайн-тест на сохранённых контекстах
(какая доля пассажей подменяется, совпадает ли с кейсами, где родитель помог — G001,
G020, G028), затем платный прогон против baseline.

- Принято: correctness не хуже baseline, полнота ссылок не хуже, контекст и цена ниже,
  чем у «всегда родитель».
- Открытый вопрос к ревью: хватает ли текущих метаданных для признака «обрывок», или
  нужен новый признак при сборке (это реиндекс — отдельное решение).

### 6. (Опционально) Родитель по решению модели

Инструмент `expand_parent(chunk_id)` только в сложном пути, лимит 1–2 вызова на запрос,
результат проходит тот же `pack_context` и бюджет. Не открытый ReAct: контракт triage
(answered / needs_context / abstain) и детерминированный граф не меняются. Замер против
шагов 4 и 5, плюс латентность и число вызовов. Делается, только если шаг 5 оставил
явные промахи.

### 7. Закрытие

FACTS.md и README на цифры baseline и итог шага 5/6; отчёт в
`docs/evaluation/experiments/`; `docs/roadmap.md` — статус «закрыт»; уборка веток и
worktree (`regulatory-rag-chunkctx`, `regulatory-rag-golden`, этот worktree) по «да» Петра.

Зависимости: 1, 2 и офлайн-часть 5 друг от друга не зависят; 3 требует готовых 2 и
ревью единого eval; 4 — после 1, 2, 3; платная часть 5 и шаг 6 — после 4.

«да» на merge #74/#75, сомнительные метки пачкой.

повторов baseline).
