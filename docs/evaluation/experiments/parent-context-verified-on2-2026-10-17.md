## Кейсы для следующего разбора

- **G052:** correctness 1→0. Ответ начал с «Верно с уточнением» вместо требуемого
  опровержения ложной предпосылки; судья нашёл противоречие эталону. Нужно проверить
  фактическую причину регрессии по ответу/контексту; причинность флага не установлена.
- **G005:** основной перечень внепланового инструктажа появился, но correctness осталась
  0: пропущены объём/сроки по ЛНА и определение работников по основанию «е».
- **G019:** correctness 0 в обоих плечах: отсутствуют оговорки эталона о массовом
  пребывании и иных объектах.
- **G028:** судья поставил 0→1, но ответ on2 не написал явно «опасные — 4 класс».
  В просмотренных контекстах обоих плеч явная формулировка «4 класс» не найдена;
  первый родительский фрагмент on2 заканчивается частью 4 статьи 14. Пропуск нельзя
  приписать флагу; это повод отдельно проверить окно и согласованность судьи.
- **Судья ссылок:** G001 — `finish_reason=length` при лимите 24000; G017 —
  `answer_quote must appear in response`. Это ошибки оценивания, не доказанные ошибки
  ответа. Платный повтор оценивания в этой сессии не запускался.

## Диагностика родителей и ограничения сбора

`parent_children_kept=47`, `parent_slots_lost=124`, `parent_truncated=0`.
Это суммы по всем проходам упаковки, включая промежуточные. `parent_slots_lost`
не доказывает вытеснение нужных норм родителями. Старый sidecar v2 не хранит
build-time truncation: нулевой счётчик не доказывает отсутствие обрезки норм.

были повторные ID и пропуски отдельных runs. Итоговые артефакты получены запросами
по одному run, с дедупликацией по feedback ID; on2 — ровно 8 ключей на каждый из
26 runs. Контроль также перечитан по одному run. Агрегаты on2 совпадают со сводкой
завершившегося раннера. В off берётся последняя оценка по ключу после прежнего rejudge.
