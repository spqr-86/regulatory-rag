# Golden 56: разбор ошибок low/off от 16.10.2026

## Итог

- Подтверждён скрытый сбой G026/low: **пустой ответ модели**, затем выдача сырых фрагментов как успешного ответа; причина установлена по исходному логу, а не предположена по нулевому usage (§ «Генератор»).
- Самая опасная новая ошибка — G034/off: суммы штрафов приписаны чужим частям статьи; faithfulness её пропускает. Номер части хранится в индексе, но не выводится в заголовок контекста (§ «Склейка и упаковка»).
- `needs_clarification` скрывает содержательные провалы G004, G011, G027, G034, G053, G055, G056; высокий faithfulness не означает полноту или правильность применения нормы (поимённая сверка ниже).
- G005/оба: все кандидаты отклонены; последний хуже предыдущего по набору незакрытых обязательств. `abstain` формирует диагностику, но раннер читает только `answer` и сохраняет пустоту (§ «Поиск и решение»).
- OOS G037/G038/G040 доходят до complex и пересказывают нормативные тексты; агрегат отказов принимает это за успех. Релевантность оценивает исполнение запроса, включая недоменный, а не уместность отказа (§ «Гейт и судья»).
- Из **56 вопросов correctness измерена на 14**: причина также в исключении `false_premise`, а не только в непроверенных эталонах. Сравнение не изолирует reasoning: меняются пути и контексты (§ «Метод»).
- Порядок работы: явный статус технического сбоя и сохранение доказательств → привязка санкций/условий к части нормы → G005 и смысловой OOS → эталоны и раздельные судьи. Текущий выбор low сохраняется; оценка выигрыша ниже — гипотеза для проверки, не результат исправленного кода.

Пути расходятся у G031/G033 (`complex → simple`) и G050/G054 (`simple → complex`), хотя общее число simple/complex одинаково (L/O `.path`). Хеши **полностью отрендеренного** промпта генерации в LL/LO совпадают у 15 вопросов и различаются у 36; хеширование — [src/infra/prompt_manager.py:80](../../../src/infra/prompt_manager.py), в лог записывается короткий префикс SHA. Совпадающие: G001, G006, G007, G015, G016, G017, G018, G022, G030, G037, G038, G043, G047, G048, G053. Короткий хеш — свидетельство совпадения входа, не сохранённый полный контекст.

Для G022 промпт одинаков (`f879e71b`), путь одинаков, low отвечает по существу, off отказывается — сильное свидетельство влияния генератора. Для G020/G028/G033/G034 промпты различаются: нельзя приписать всю разницу только reasoning. Expander также вызывается заново: [src/v7/bridge.py:700](../../../src/v7/bridge.py); он получает `thinking_budget=0`, однако результат expansion не фиксируется между плечами. Одинаковые снимок и вопрос не означают одинаковую выдачу. Замеры complex не являются A/B по effort: там в обоих случаях low, а различия могут происходить от выдачи, стохастики и маршрута провайдера.

## Генератор: скрытый сбой и неверное применение нормы

### G026/low — причина установлена

Подтверждены все симптомы из задания: единственный непустой ответ без маркера `Фрагмент`, нет `Вывод`, `usage[node=generate]` содержит нули и `n_passages=0`, при этом faithfulness=1.0, relevance=0.4 (L/G026). Ответ разбит по двойному переводу строки на 10 блоков; каждый **дословно** совпал с документом из SQLite текущего снимка. Это склейка сырого контекста, не синтезированный ответ.

В LL сохранено:

```text
2026-10-16T12:52:32.988330Z generate.timing.context:
  passages_in=30 passages_out=30 prompt_tokens_approx=5331
2026-10-16T12:52:38.742709Z warning:
  LLM generate failed after retries: Empty generation response, falling back to stub
```

Механизм: `llm.invoke` вернул response, `extract_text(response.content).strip()` пуст; [bridge.py:412](../../../src/v7/bridge.py) выбрасывает `ValueError("Empty generation response")`. Обработчик `:462` возвращает первые 10 пассажей и нулевой usage. Комментарий `:467` «call never reached the model» этому случаю не соответствует: вызов завершился пустым содержимым. Фраза лога «after retries» не доказывает, что были ретраи: на пустую строку отдельного retry-цикла здесь нет.

**Установленная причина на уровне приложения — пустой извлечённый ответ.** Почему response оказался пустым (reasoning-only, provider finish reason, лимит, иной формат content) — не проверено: сырой response/finish_reason/usage не сохранены, трейсов нет. Это не подтверждённая ошибка HTTP/API. У O/G026 генерация успешна, но вместо привязки штрафов к составам дана подборка сумм без полного контекста применения.

Что чинит код: явный `generation_failed`, безопасный пользовательский ответ об ошибке, сохранение exception type и доступного response usage до проверки пустоты; fallback не должен имитировать юридический ответ. Успешность транспорта, наличие текста и качество ответа должны быть разными признаками. Одна только правка судьи скрытый сбой не устранит.

Порог centroid нельзя просто поднять: можно потерять короткие и пограничные вопросы по ОТ.

### Цитаты и контекст

Проверены все непустые ответы: у L только G026 не содержит маркера вида `[Фрагмент N…]`/`[Фрагменты …]`; у O таких нет. У пустых записей цитирование неприменимо. Числовые ссылки `Фрагмент N`, извлечённые из ответов, не выходят за `usage[node=generate].n_passages` ни в одном успешном вызове; это только диапазон номеров, не доказательство правильной цитаты. Множественные ссылки вида `[Фрагмент 1, 22]` и диапазоны требуют нормального парсера, а не одного regex по строгому `[Фрагмент N]`.

**Дословное соответствие каждой цитаты её историческому контексту не проверено:** runner строит context из `final_passages`, но не сохраняет его в итоговый JSON (`run_query :210`, `record_fields :237`, сборка записи `:489`). Кроме того, этот judge-context лишён заголовков/нумерации, которые видит генератор через `format_generation_context`; точность адресации судья F полноценно не оценивает. Полных промптов в LL/LO нет: они логируются только при DEBUG ([prompt_manager.py:90](../../../src/infra/prompt_manager.py)).

Найден **подтверждённый случай неверной привязки цитируемого содержания** G034/O: реальные суммы приписаны чужим составам. Случаи с буквальной цитатой, отсутствующей в `final_context`, по имеющимся данным ни подтвердить, ни исключить нельзя. Перечитывание индекса сейчас не восстанавливает порядок исторической выдачи. Не следует подменять этот пробел утверждением «галлюцинаций цитат нет».

## Приложение: все вопросы и оба исхода

### Правила чтения таблиц

В таблице A дан смысловой результат чтения `.answer` обоих плеч. В таблице B — все 112 исходов из L/O, по каждому путь/время/токены/оценки/класс. Источник каждой строки B: L или O, `results[case_id=…]`; статус эталона — `reference_status` этого же результата и D. Никакие пропуски не заполнены выдуманными нулями.

`P/C/Rsn` = prompt/completion/reasoning (reasoning является частью completion). `F/Rel/Corr` = faithfulness/relevance/correctness. `—` = поле отсутствует либо score не запускался; это не нулевая оценка. `V` = verified, `N` = needs_clarification. Класс `верно` — ручная оценка основного ответа в пределах локального источника, не новый числовой score. `НЭ` = нет проверенного эталона; уточнение после него — предварительная содержательная оценка. `ошибка судьи` может сосуществовать с неполным ответом. У OOS «отказ» описывает фактическое поведение, а не автоматически полный успех продукта. Путь `simple*` пустого OOS — классификация раннера без доказательства запуска simple retrieval.
