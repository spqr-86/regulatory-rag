# Руководство по тестированию

Как проверить, что документация и код актуальны и корректны.

## Что проверять

### 1. Ссылки и перекрёстные ссылки

- **Внутренние ссылки:** Убедиться, что все ссылки на файлы в документации (например, `[код](src/main.py)`) ведут к существующим файлам.
- **Внешние ссылки:** Проверить, что URL открываются и ведут к актуальным ресурсам.
- **Изображения:** Убедиться, что все изображения отображаются корректно.

### 2. Примеры кода

- **Команды установки:** Выполнить установку зависимостей (`pip install -r requirements.txt`) в чистом окружении и убедиться, что всё работает.
- **Примеры запуска:** Выполнить примеры кода из README и руководств. Они должны работать без ошибок.
- **Конфигурация:** Проверить, что примеры конфигурационных файлов (например, `.env.example`) актуальны и содержат все необходимые параметры.

### 3. Версии и зависимости

- **Согласованность версий:** Убедиться, что версии библиотек, упомянутые в документации, соответствуют `pyproject.toml` или `requirements.txt`.
- **Совместимость:** Подтвердить, что требования к версии Python и ОС актуальны.

### 4. Структура проекта

- **Дерево файлов:** Если в документации есть структура директорий, сравнить её с реальным расположением файлов. Удалённые или перемещённые файлы должны быть отражены в документации.
- **Описания модулей:** Убедиться, что описания файлов и директорий соответствуют действительности.

## Процедура

1. Прочитать изменённые или новые файлы документации.
2. Пройти по чеклисту выше.
3. Использовать автоматические средства проверки ссылок, если они настроены, или проверять вручную.
4. При обнаружении неточностей — исправить немедленно или создать задачу в бэклоге.
