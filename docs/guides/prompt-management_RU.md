# Управление промптами

## Обзор

Все промпты пайплайна V7 (генерация, верификация, переформулировка, расширение) хранятся как версионированные
Jinja2-шаблоны и загружаются во время выполнения через `PromptManager`. Это отделяет текст промптов от
Python-кода и позволяет переключать версии без деплоя.

- **Шаблоны:** директория `prompts/` (файлы Jinja2 `.j2`)
- **Реестр:** `prompts/registry.yaml` — связывает логический `prompt_id` с версионированными путями к файлам
- **Связанное:** `config/term_glossary.yaml` — детерминированное расширение доменных аббревиатур (не Jinja2, но часть prompt engineering)

---

## Структура директории

```text
prompts/
├── registry.yaml              # Глобальный реестр версий
├── common/
│   └── base_rules.j2          # Макрос BASE_RULES (10 граничных случаев)
├── agents/
│   ├── generate_answer_v1.j2  # Промпт генерации ответа (активный)
│   ├── query_expand_v1.j2     # Промпт расширения запроса (активный)
│   └── ...
└── chains/
    └── ...
```

---

## Реестр (`registry.yaml`)

Связывает логический `prompt_id` с конкретными версионированными шаблонами.

```yaml
applicability_retriever:
  active_version: "v2"
  versions:
    v1: "agents/query_expansion_v1.j2"
    v2: "agents/query_expansion_v2.j2"
```

---

## Использование в коде

Загружать промпты через `PromptManager`:

```python
from src.infra.prompt_manager import PromptManager

manager = PromptManager()

prompt_text = manager.render(
    prompt_id="research_agent",
    question="Что такое СИЗ?",
    documents=[doc1, doc2]
)

llm.invoke(prompt_text)
```

`PromptManager` использует `StrictUndefined` — если переменная шаблона отсутствует, сразу выбрасывается
исключение, а не отправляется сломанный промпт в LLM.

## Переключение версий (Pinning)

Переопределить активную версию конкретного промпта через переменную окружения без изменения кода или реестра:

```bash
# Формат: PROMPT_{PROMPT_ID}_VERSION={VERSION}
export PROMPT_RESEARCH_AGENT_VERSION=v2
python app.py
```

Случаи применения:
- Локальная отладка новой версии промпта
- A/B тестирование в CI
- Быстрый откат в продакшне

## Безопасность и логирование

1. **Защита от path traversal:** Реестр блокирует абсолютные пути и `..` — нельзя прочитать произвольные файлы с диска.
2. **Privacy-first логирование:** По умолчанию логируется только SHA256-хэш промпта и имена переменных. Текст промпта (который может содержать PII) не логируется. Установить `DEBUG_PROMPTS=true` для логирования полного текста при отладке.

## Продвинутые техники

### Chain-of-Thought (XML-теги)

Шаблоны используют XML-теги `<thought>` / `<answer>` для разделения рассуждений и финального ответа.
Код агента разбирает эти теги, UI может отображать рассуждения в сворачиваемом блоке.

### Макрос BASE_RULES

`prompts/common/base_rules.j2` — общий макрос `{% macro base_rules() %}`. Содержит:
- Абсолютные запреты (никаких галлюцинаций, никакой экстраполяции)
- Правила предобработки запроса (содержание vs. идентификаторы)
- 10 граничных случаев (устаревшие ссылки, перекрытие документов, отрицательные вопросы, интеграция глоссария, fallback для неизвестных аббревиатур и т.д.)
- Правила формата ответа (прямой ответ, дословные цитаты)

### Term Glossary

`config/term_glossary.yaml` — YAML-словарь неофициальных доменных аббревиатур.
Логика расширения находится в `src/glossary.py` (`expand_query_with_glossary`), используется роутером V7.
Применяется детерминированно:
- Слова >4 букв матчатся по морфологическому стему; аббревиатуры ≤4 букв матчатся как целое слово
- К запросу добавляется блок `[Глоссарий: term → expansion]`
- Fallback: инструкция LLM для терминов, отсутствующих в глоссарии (случай 10 в BASE_RULES)

## Валидация

`scripts/validate_prompts.py` проверяет:
- YAML-структуру реестра
- Существование всех файлов, на которые ссылается реестр
- Отсутствие дублирующихся ключей версий

Запускать после любых изменений промптов:
```bash
python scripts/validate_prompts.py
```
