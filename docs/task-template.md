# Шаблон грумленой задачи

Текст issue после груминга состоит ровно из этих разделов.

```markdown
## Цель

Одно-два предложения: что становится возможно, когда задача сделана. Формулировка от лица
того, кому это нужно (пользователь системы, разработчик проекта, автор портфолио), а не
от лица кода.

## Контекст

Ссылка на спек / раздел роадмапа / соседние issues. Что уже есть в репозитории и чего нет.
Три-пять строк, без пересказа спека.

## Объём

Маркированный список того, что делается. Конкретные файлы и сущности, если они уже известны.

## Acceptance criteria

- [ ] Проверяемый пункт: команда, которую можно запустить, или экран, на который можно ткнуть.
- [ ] ...

Каждый пункт формулируется так, чтобы «да/нет» ставил человек, не читая код.

## Вне объёма

- Что сознательно не делаем в этой задаче и почему (одна строка на пункт).
- Если пункт всё-таки нужен — он становится отдельной issue, ссылка здесь же.

## Крайние случаи

- Ситуация → ожидаемое поведение. Либо явное «не обрабатываем, см. вне объёма».
```
