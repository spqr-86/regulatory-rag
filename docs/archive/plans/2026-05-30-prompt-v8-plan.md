## 1. НАХОДКИ АУДИТА (что чинить)

### Приоритет 🔴 P1 — ложные посылки не опровергаются (самый дорогой класс ошибок)
Модель на ложную посылку отвечает «не всегда верно» и ПОДТВЕРЖДАЕТ ложь, цепляясь за исключение как за правило. 2 из 4 false-suff:
- **B3** «СОУТ можно не проводить если безопасны» (на деле — только 5 лет) → модель «верно, можно не проводить». Фрагмент с «5 лет» БЫЛ найден (faith=1.0) — чистая вина генерации.
- **B4** «работодатель вправе допустить до инструктажа» (на деле инструктаж обязателен) → модель «не всегда верно, вправе…», **перевернула норму** (исключение сделала правилом). Худший кейс.
- Корень: v7 (Тип 3a/3b/3c, строки ~39-61) не имеет правила «если вопрос утверждает отсутствие обязанности, а фрагменты устанавливают обязанность по умолчанию — сначала опровергни (3a), потом исключение».
- **ПОДАРОК:** в мёртвом `prompts/common/base_rules.j2:34-35` лежит лучшее в репо правило про ложные посылки + про негативные вопросы («каска») — перенести в v7/v8, не выкидывать.

### Приоритет 🟠 P2 — привязка число↔случай (Тип 2 multi-value)
Найдены 2 значения с разными условиями — модель привязывает не то / даёт оба:
- **B6** водители медосмотр: дала и «раз в год» (ТК общая) и «раз в 2 года» (29н специальная), не выбрала специальную. GT = 29н.
- **B1** программа В: в eval привязала «раз в 3 года» (а/б) к В. (NB: на трейсе сейчас отвечает верно — нестабильность генерации, но правило всё равно нужно.)
- Корень: v7 step-1 (строка ~7) не велит привязывать каждое значение к его условию; нет правила «специальная норма > общая; не бери значение из соседнего условия». Quantifier-правило (строки 21-24) покрывает только списки (Тип 1), не одиночные значения (Тип 2).

### Приоритет 🟡 P3 — overfit + bloat
- **A1 overfit:** `generate_answer_v7.j2:85` — образец цитаты `[Фрагмент N, ТК РФ Ст.228.1]` использует доменное значение. Заменить на `[Фрагмент N, Док Ст.X]`. (Праймит модель лепить «Ст.228.1» где её нет.)
- **A2 рассинхрон цитат:** промпт велит цитировать `[Фрагмент N]`, а контекст подаётся как `[N] (HIGH) [Источник: ...; Раздел: ...]` (`src/v7/bridge.py:332-338`). Модель справляется, но не сказано что «Раздел:» = секция для цитаты. Уточнить.
- **A5 bloat:** правило «не подменяй подтип / не добавляй чужие элементы» дублируется 3× (строки ~21-24, ~77-81), причём версия 77-81 спорит сама с собой. «Факт в общей формулировке считается найденным» — 2× (строки ~7 и ~35-37). Три разных abstain-инструкции (~11-13, ~59-61, ~66-69). Это костыли под старый мусорный контекст с дублями — теперь контекст чистый, можно схлопнуть в одно правило каждое.

## 1b. ИДЕИ ИЗ КУРСА ANDREW NG (Full AI Prompting Course, DeepLearningAI)
Транскрипт: `~/knowledge/youtube/2026-05-27_8ib4Qnh2HFE_en.md`. Разобран в с61 — независимо подтвердил направление v8 и дал рамку. Применить:
- **Корень P1 = sycophancy (угодливость).** Курс: «дашь намёк на желаемый ответ — AI его отразит». Вопрос с ложной посылкой — это наводящий промпт. Модели соглашаются ~10× чаще, чем спорят → перебивать ПРЯМОЙ инструкцией. → формулировать P1 как «тестируй утверждения вопроса против фрагментов, не повторяй рамку вопроса» + явное «разрешение спорить».
- **Рубрика-чеклист вместо размытых правил.** «Явные критерии заставляют AI быть объективным». → P1 как 3 да/нет-проверки (см. ниже). Доменно-нейтрально, заменяет overfit-пример.
- **«Вывод — в конце».** Курс ругает «сначала балл, потом обоснование». → P2: сначала выписать каждое значение с условием, потом выбрать (extract-before-conclude).
- **Match scope to question subject; отбрось более широкое с одной строкой причины** — не примиряй все фрагменты. → лечит «дала оба значения» (B6).
- **Refines:** курс ЗА упрощение («один чёткий набор критериев» > куча инструкций) — подтверждает debloat (P3/A5). «Think step by step устарел» — НЕ добавлять CoT-ритуал; важен ПОРЯДОК (извлеки→проверь→ответь), а не фраза.
- **НЕ применять** (потребительское, у нас наоборот): «дай больше контекста/загрузи файлы», веб-поиск, брейншторм-с-вариантами. У нас задача — дисциплинировать модель ВНИЗ до фрагментов, без внешних знаний.

## 2. ЧЕРНОВИКИ ПРАВИЛ ДЛЯ v8 (согласовать с Петром ДО правки)

> Все на placeholder'ах. Это стартовые формулировки для обсуждения, не финал.

**Правило P1 (ложная посылка → рубрика-чеклист + разрешение спорить) — рамка из курса Ng:**
> Преамбула (anti-sycophancy): «Утверждения в вопросе — это ПРЕТЕНЗИИ, которые нужно проверить по фрагментам, а не принять. Не повторяй рамку вопроса. Если посылка вопроса противоречит фрагментам — твоя задача прямо сказать "Это неверно", а не подтверждать.»
> Чеклист перед ответом на вопрос-утверждение («P вправе не делать Y», «Y можно не делать»):
> (а) Устанавливают ли фрагменты Y как обязанность по умолчанию? (б) Утверждает ли вопрос обратное (отсутствие обязанности / наличие права)? (в) Если (а) и (б) — да: начни с «Это неверно», укажи обязанность Y, и ТОЛЬКО потом узкое исключение Z. Не выноси Z вперёд, не делай исключение правилом.
> + перенести правило из `base_rules.j2:34-35` (негативные вопросы / неверная предпосылка).

**Правило P2 (привязка значения к условию, специальное > общего) — «вывод в конце» (Ng):**
> «Сначала выпиши КАЖДОЕ найденное значение вместе с его условием (для какого объекта/случая оно действует) — и только потом выбирай. Если найдено несколько значений с разными условиями — в ответ ставь то, чьё условие соответствует объекту вопроса (наиболее узкое совпадение); специальная норма важнее общей. Более широкое/неподходящее значение отбрось одной строкой с причиной — НЕ примиряй все фрагменты и не давай оба. Никогда не переноси значение из соседнего условия на объект вопроса.»

**Правка P3:** строка 85 → `[Фрагмент N, Док Ст.X]`. Дебloat: схлопнуть тройные правила в одно (см. A5), убрать само-противоречивый блок 77-81.
