- `generate_answer v7` — мягкое "не подменяй подтип"

## Что применили (по порядку)

1. **CrossEncoder + sigmoid** (вместо FlashRank) — false-sufficiency 22.9% → 15%, но correctness просел 6.3 → 6.1. Дальше — на CrossEncoder.
2. **Prompt v3** — добавили "comprehensive synthesis" — correctness 6.1 → 6.6, но регрессии (модель over-abstain).
3. **Prompt v4** — Extract-first алгоритм, 4 шага — 6.6 → 6.9, faithfulness 0.874 (target!), но регрессия "стажировка" (echo ложной предпосылки).
4. **Prompt v5** — мини-примеры вместо абстрактных правил — 6.9 → 7.2, false-sufficiency 0%, но over-enumeration на программе А/штрафе.
5. **Prompt v6** — добавили "не подменяй подтип" (квалификатор вопроса фильтрует элементы) — 7.2, faithfulness 0.833.
6. **Section headers в чанк** — добавили `Раздел: Ст.228.1` в шапке чанка для генерации — correctness 7.2 → 7.3, ФСС срок 3 → 7.

## Оставшиеся рычаги

- **Приказ 29н полный** — состав медосмотра (касается #12)

Оценка impact: +0.3-0.5 на in-scope correctness.
Стоимость: ручная работа по поиску актуальных версий + reindex.

### C. HyDE (касается 1-2 вопросов)
- LLM генерирует "идеальный ответ" → embedding ищет по нему
- Лечит retrieval miss (#4 изменение технологии, частично #12 медосмотр)
- Доп. LLM-вызов на каждый запрос (+ $0.001 / +200ms)

Оценка impact: +0.1-0.2 на in-scope correctness.
Стоимость: реализация + cost increase.

### D. Multi-query expand с keyword anchors
- Для перечневых вопросов — генерировать sub-queries по типам
- Лечит multi-source synthesis (#5, #15, #19)

Оценка impact: +0.1-0.3.
Стоимость: реализация + +1 LLM-вызов.

### E. Откатить v6 регрессии
- "А и Б ежегодно" 9→5 — модель ушла в abstain под влиянием quality filter
- "Ответственность за ОТ" 7→5 — section headers сбили
- Локальные правки промпта чтобы не over-filter

Оценка impact: +0.1.
Стоимость: минимум.
