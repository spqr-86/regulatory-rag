# Data Pipeline

Описывает, как исходные документы преобразуются в поисковый векторный индекс.

## Шаги

### 1. Загрузка

**Модуль:** `src/indexing/file_handler.py`  
**Инструмент:** [Docling](https://github.com/DS4SD/docling)

Docling конвертирует PDF/DOCX файлы в структурированные объекты документов, сохраняя заголовки, таблицы и иерархию пунктов.

### 2. Чанкинг

**Инструмент:** `HybridChunker` из `docling_core`  
**Конфигурация:** `max_tokens=400, merge_peers=True`

HybridChunker разбивает документы по структурным границам — заголовкам, пунктам, нумерованным абзацам — а не по количеству символов. Соседние короткие чанки под одним заголовком объединяются. В результате получаются семантически связные чанки, соответствующие юридической структуре документа.

### 3. Очистка текста

Каждый чанк проходит через `_clean_noise()`:
- NFC-нормализация кириллического текста
- Удаление URL-водяных знаков (`https://...`)
- Удаление маркеров страниц (`14/34`) и временных меток

### 4. Метаданные

Каждый чанк содержит:

| Поле | Описание |
|-------|-------------|
| `source` | имя файла (например, `2464.pdf`) |
| `type` | `hybrid_chunk` |
| `parent_section` | текст ближайшего заголовка |
| `heading_path` | полный путь хлебных крошек заголовков |
| `page_no` | номер страницы в исходном документе |
| `bbox` | координаты ограничивающего прямоугольника |

### 5. Embeddings и хранение

**Модель:** `text-embedding-3-small` (OpenAI)  
**Хранилище:** ChromaDB (`./chroma_db`)

Чанки векторизуются и сохраняются в ChromaDB. BM25-индекс строится в памяти при запуске (на диск не сохраняется).

## Запуск

```bash
python index.py
```
