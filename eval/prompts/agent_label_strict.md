# Строгий разметчик held-out (агентный путь)

Ты размечаешь эталон для поисковой системы по нормативной базе (охрана труда,
пожарная безопасность). Промпт повторяет `STRICT_PROMPT` из
`eval/label_golden_retrieval.py`: агентный и платный пути должны судить по одному
критерию, иначе эталоны несравнимы.

ВХОД: `eval/data/pools_ext/shard_NN.json` — массив
`{"n", "question", "candidates": [{"index", "chunk_id", "source", "text"}]}`.
Прочитать файл целиком (~220 КБ).

ЗАДАЧА: для КАЖДОГО вопроса указать фрагменты, которые ДЕЙСТВИТЕЛЬНО отвечают на него.

Ты — строгий разметчик. По умолчанию фрагмент не подходит; включай его, только если
убедился. Критерий один: во фрагменте есть текст, из которого человек получит ответ
на заданный вопрос. Не «фрагмент про ту же тему», не «фрагмент из нужного документа»,
а именно ответ.

Для каждого включённого фрагмента выпиши в `quote` ДОСЛОВНУЮ фразу из его поля `text`.
Цитата проверяется автоматически вхождением подстроки: фразы нет в тексте — метка
бракуется. Не восстанавливай норму по памяти. Выписать нечего — фрагмент не включать.

Фрагментов-ответов может быть несколько (норма продублирована, ответ разбит по пунктам) —
укажи все. Ни один не отвечает — пустой `relevant`: это нормальный исход, поиск мог не
найти ничего.

Заголовок в начале фрагмента бывает от чужого раздела — дефект нарезки корпуса. Суди по
тексту нормы, а не по заголовку.

ВЫХОД: `eval/data/verdicts_ext/shard_NN.strict.json`, валидный JSON в UTF-8, без
markdown-обёртки:

```json
{"pass": "strict", "verdicts": [{"n": 1, "relevant": [{"index": 3, "quote": "дословная фраза"}], "note": ""}]}
```

Ровно одна запись на каждый вопрос входного файла, с тем же `n`: пропущенный вопрос
ломает сборку (`ingest_agent_labels.py` падает, а не размечает его молча пустым).
