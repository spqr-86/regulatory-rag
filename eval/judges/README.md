# Citation judge — учебный черновик

Практика по LangChain Academy, курс Reliable Agents, модуль 2,
[LLM-as-a-Judge](https://langchain-ai.github.io/lca-lessons/reliable-agents/module-2/llm-as-judge).
Применяем материал курса к regulatory-rag. Код пишет учащийся;
ассистент объясняет по одному шагу, проверяет и запускает офлайн-тесты.

## Контракт

Вход: вопрос, ответ RAG и точные фрагменты, переданные генератору.
Модель сопоставляет документ, раздел и пункт/подпункт/статью для каждого
положения, возвращает только `checks`. Каждая запись содержит `field`,
`answer_quote`, `context_quote`, `comparison`, `reason`.

Код проверяет, что указанные цитаты действительно присутствуют в своих
текстах, и вычисляет статус: `mismatch`/`missing_in_answer` дают `fail`;
иначе `unverifiable` даёт `needs_review`; только `match` дают `pass`.
Пустой массив даёт `needs_review`. Выдуманные цитаты — ошибка формата
ответа судьи (`ValueError`), а не ошибка оцениваемого RAG.
Семантическое сравнение остаётся задачей модели.

## Текущее ограничение и следующий шаг

**Полный вызов пока несовместим с новым контрактом:** `CITATION_PROMPT`
просит только `checks`, но `parse_verdict` требует общие `status` и `reason`.
Следующий учебный шаг — обновить парсер под новый контракт:
массив `checks`, записи-объекты, обязательные поля, допустимые значения
`field`/`comparison` и непустой `reason` в каждой записи.
Затем проверить полный вызов `judge_citations` с подставной моделью
и обновить офлайн-тесты. Ранее подготовленные локальные тесты для
`validate_quote_evidence`/`aggregate_verdict` не соответствуют выбранной
единой функции `validate_and_score` и в этот черновик не включены.

Офлайн проверены основные статусы, приоритет `fail`, выдуманные цитаты,
неизвестный `comparison`, обязательность обеих цитат для `match`/`mismatch`
и доказательство пропуска для `missing_in_answer`. Сборка нового промпта
проверена; его качество на реальной модели ещё не измерено.

Ранее судьи GPT-4o и DeepSeek пропускали отсутствие раздела в реальном
ответе, хотя раздел был доступен во фрагментах. Это причина перехода
к отдельным цитатам и вычислению итогового статуса кодом.

`run_citation_example.py` делает три реальных вызова модели через фабрику
проекта. Запускать только после исправления парсера и отдельного разрешения
на платный прогон. Не менять production, индекс, RAG graph или общие
настройки модели для продолжения этого упражнения.
